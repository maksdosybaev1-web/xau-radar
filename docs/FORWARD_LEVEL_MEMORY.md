# Очистка завершённых уровней SBR/RBS

Дата: 27 сентября 2026.

Живые обёртки SBR/RBS после успешной обработки свечи удаляют из `model.levels` уровни в состояниях `expired`, `context_rejected`, `invalidated`, `retest_unconfirmed`, `entry_rejected`, `signal_ready`, `incomplete`, `closed`. Эти состояния больше не обрабатываются ветками поиска пробоя и возврата. Идентификатор нового уровня включает время свечи и время обнаружения, поэтому удаление старого уровня не создаёт повторный уровень на следующих свечах.

Очистка выполняется только для `signals_only`, после записи новых событий в JSONL и передачи уведомлений в локальную очередь. Если обработка завершилась исключением, уровни остаются в памяти. Действующие уровни, неизвестные состояния и уровни, на которые ссылается наблюдаемая сделка, сохраняются. Исторические исследовательские модели не изменены.

Журнал переходов и данные уведомлений остаются на диске. Это не архив полных объектов уровней: разогрев, как и раньше, не входит в forward-журнал. После перезапуска живые модели строят контекст заново из свечей.

Проверка: `python -m unittest discover -s tests -q` — 154 теста прошли. На 3 600 синтетических M1 для каждого режима подтверждено совпадение всех событий с моделью без очистки и совпадение оставшихся активных уровней. Отдельно проверены защита исторического режима, сохранение неизвестных состояний и ссылок наблюдаемых сделок, ошибка очереди и сохранность цены, уровня, стопа и цели в записанном уведомлении до удаления уровня. Эти проверки не оценивают прибыльность.

Следующее ограничение памяти: множество ключей `seen` всё ещё растёт с журналом. Остальные подсистемы также требуют отдельной оценки; вся память радара этим изменением не ограничена.

Радар, MT5-мост и Telegram не запускались, реальные сообщения не отправлялись.
