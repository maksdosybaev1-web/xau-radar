# Forward-наблюдение вложенной цепочки

27 сентября 2026 года к читающему мосту MT5 подключены наблюдатель M15 → M5 → M1 и две отдельные трактовки первого возврата: `touch_limit` и `after_close`. Мост читает только закрытые M1 и не вызывает торговые API. Кандидат по закрытию записывается лишь после появления следующей M1; если её нет, фиксируется `missing_next_m1`. Оба режима остаются кандидатами, а не подтверждёнными брокером исполнениями.

Граница новых данных сохранена как **2026-09-27 09:20:29 UTC** (`forward_since=1790500829`). При перезапуске мост восстанавливает контекст из истории и подавляет повторную запись событий по устойчивому ключу. События, впервые восстановленные позже их закрытия, получают метку `late_bar`; пятничная история не становится свежими событиями. Журнал: [`results/nested_forward_events.jsonl`](../results/nested_forward_events.jsonl), состояние: [`results/nested_forward_live.json`](../results/nested_forward_live.json). Локальный API: `http://127.0.0.1:8767/api/nested-live`; скачивание журнала: `http://127.0.0.1:8767/download/nested_forward_events.jsonl`.

На момент запуска последняя котировка XAUUSD — **2026-09-25 22:59:59 UTC**. Мост обновляет состояние, исторический контекст готов, `stale=true`, число новых событий равно **0**. Поэтому forward-исходов и сравнения режимов на новых данных пока нет. Telegram для этой исследовательской модели выключен; существующие уведомления SBR/RBS продолжают работать отдельно.

Для покупок MT5 даёт bid OHLC, а ask OHLC мост оценивает по спреду M1. Такая оценка и пересечение свечой уровня не подтверждают реального касания ask, очереди лимитной заявки или исполнения. Журнал сохраняет `quote_quality`, `observation_quality`, время котировки и `result_status=not_evaluated`. Перед выводами о качестве режима нужны свежие события и проверка по тикам и фактическим условиям брокера.

Проверено: 112 тестов (`python -m unittest discover -s tests -q`), включая границу forward-журнала, отсутствие дублей после перезапуска и ожидание следующей M1. После перезапуска моста и локального сервера `/api/nested-live` вернул `ready=true`, `stale=true`, `bridge_stale=false`, `forward_events_total=0`; скачивание пустого журнала вернуло HTTP 200.

## Расчётные исходы на будущих M1

К мосту добавлен отдельный [`nested_forward_outcomes.jsonl`](../results/nested_forward_outcomes.jsonl). Он применяет заранее описанные в [спецификации исходов](ENTRY_MODES_OUTCOME_SPEC.md) стоп, цель, расходы и фильтр спреда к **новым** кандидатам. Пока после кандидата нет достаточного числа закрытых M1, опыт остаётся ожидающим; после появления исхода записывается один окончательный статус (`closed`, `rejected`, `not_eligible`, `entry_bar_path_unknown` либо `incomplete`). На перезапуске уже записанные исходы не дублируются. Это независимые бумажные опыты по M1, без подтверждения брокерского исполнения и с оценёнными ask OHLC.

После обновления прошли **113 тестов**, включая синтетический опыт, который остаётся ожидающим до следующей M1, затем закрывается и не удваивается при перезапуске. Живой API `/api/nested-live` показывает `paper_outcomes_total=0`, `paper_outcomes_pending=0`, `stale=true`, `bridge_stale=false`; скачивание пустого журнала исходов возвращает HTTP 200. Новых котировок и реальных forward-исходов по-прежнему нет.

## Проверка первого касания по тикам

Для каждого нового `touch_observed` мост после сбора bid/ask тиков отдельно проверяет минуту первого возврата и пишет результат в [`nested_forward_tick_checks.jsonl`](../results/nested_forward_tick_checks.jsonl). Запись содержит покрытие запросами, первую котировку внутри M1-зоны, первую котировку за порогом лимита, спред и время первого получения тика. Если котировка найдена, это свидетельство наблюдавшейся цены, **не подтверждение исполнения заявки**. Отсутствие совпадения при `queried_unverified` означает только отсутствие его в запрошенных тиках; непокрытая минута получает `insufficient_tick_coverage`. Неполный запрос не превращается в отрицательный результат сразу: мост ждёт до 90 секунд после закрытия минуты. Проверка сохраняется один раз и не удваивается после перезапуска.

Прошли **116 тестов**, включая положительное совпадение, ожидание при отсутствии тиков и подавление дубля. После обновления `/api/nested-live` показывает `tick_checks_total=0`, `tick_checks_pending=0`, `stale=true`, `bridge_stale=false`; новый пустой журнал доступен на `/download/nested_forward_tick_checks.jsonl` (HTTP 200). Рыночных тиков после границы forward пока нет, поэтому это проверка механизма, не его точности на новом рынке.
