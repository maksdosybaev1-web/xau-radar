# Оптимизация памяти forward-журнала FVG

Дата: 27 сентября 2026.

`FVGForward` использует общий `JournalKeys` вместо множества ключей в памяти и `ReplayPending` вместо загрузки всех старых уведомлений в словарь. Ключи находятся в SQLite рядом с JSONL; восстановление очереди читает по одной записи. Сначала проверяется принадлежность всего журнала источнику и версии правил, затем строится индекс и готовится восстановление. Совместимость со старыми записями без `source_hash` сохранена.

Источником истины остаётся JSONL. При новом событии журнал записывается с `flush()` и `fsync()` до обновления индекса. После последующего исправления ошибка индекса восстанавливается также без перезапуска. Новый ключ включает ID зоны и распознаёт старые записи. Содержание сообщений и правила давности/разрешения доставки не менялись.

Проверка: `python -m unittest discover -s tests -q` — 161 тест прошёл. Добавлены проверки сбоя индекса с восстановлением без повторной записи, отказа при чужом источнике или версии до перестройки индекса/передачи уведомлений, восстановления 1 000 записей без предварительной загрузки уведомлений в словарь. Прежние тесты проверяют приближение, подтверждение, отмену, устаревшие события, выключенную доставку и отсутствие повторной отправки.

Границы: весь журнал по-прежнему проверяется при запуске; индекс строится отдельным последовательным проходом, а восстановление уведомлений выполняется ещё одним проходом при первом вызове. Это экономия памяти, не гарантия быстрого запуска большого архива. Курсор восстановления не сохраняется между запусками. Размер файлов на диске не ограничен. Списки событий, сделок и кривая капитала самого FVG-движка этим этапом не изменены.

Радар, MT5-мост и Telegram не запускались. Все проверки выполнены на временных файлах; реальные уведомления не отправлялись.
