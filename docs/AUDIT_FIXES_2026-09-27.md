# Исправления после повторного аудита

27 сентября 2026. Выполнен этап устранения четырёх воспроизведённых проблем; новые торговые модели не добавлялись.

## Telegram и служебные статусы

Добавлены ограниченные повторы замены файла heartbeat при `PermissionError` Windows. Сбой диагностической записи теперь изолирован от worker: ни ошибка обычного статуса, ни ошибка записи статуса ошибки не завершают доставку. Ошибка инициализации SQLite также допускает повтор в следующем цикле.

Регрессионный тест моделирует ошибку базы, одновременные отказы heartbeat и последующее восстановление обработки. После перезапуска API показывает `worker_alive: true`, «Очередь работает»; мост работает, журналы ошибок пусты. Проверка интерфейса Chromium прошла. Новое сообщение в Telegram для проверки не отправлялось, фактическая доставка свежего рыночного сигнала на этом этапе не проверена.

## Восстановление очереди SBR/RBS

В новую запись forward-журнала вместе с событием помещается полный payload уведомления и исходная настройка включения доставки. Запись сбрасывается на диск до обращения к очереди. Если SQLite временно недоступна, запись остаётся в списке восстановления; повтор выполняется при следующем обновлении. После перезапуска список восстанавливается из журнала.

Стабильный ID и `INSERT OR IGNORE` сохраняют существующий статус, в том числе `sent`/`sending`; повторная отправка подтверждённого сообщения не создаётся. Прежние ограничения свежести сохраняются: устаревшие сигналы не отправляются поздно. Сообщение, созданное при выключенной доставке, не превращается в Telegram-уведомление после её включения. Тесты проверяют обе ветки, перезапуск, уже отправленный ID, просрочку и выключенную доставку.

Воспроизведение из аудита теперь даёт 1 запись журнала и 1 запись очереди вместо 1 и 0. Старые записи без нового payload автоматически восстановить этим механизмом нельзя. Во время исправления рабочий журнал рыночных уведомлений пуст. Решение не заявляет транзакцию между JSONL и SQLite: это восстановление из предварительно сохранённой записи.

## ИИ-сводка

Причины теперь выбираются из фактических счётчиков, включая равенство частот и отсутствие причин. Числа парных и новых исходов подставляются из данных; фиксированные заявления об их отсутствии удалены. В таблицу добавлена строка «Не допущено к входу», чтобы не смешивать `not_eligible` и `rejected`.

По самим закрытым опытам пересчитываются победы, средний R и пересечение `candidate_id` между режимами. Несогласованная сохранённая сводка отклоняется. Проверяются конечность R и дубликаты закрытых кандидатов. Верхний уровень ответа модели должен быть JSON-объектом; `[]`, `null`, число и строка корректно отклоняются через `ValueError` с переходом к числовой сводке.

[Итоговая сводка](../results/ai_journal_review.md) заново сформирована командой `python -X utf8 -m app.ai_journal --no-model`. Новый вызов Ollama не выполнялся, фильтрация сделок ИИ не включалась. Семантическая проверка свободного текста остаётся ручной; прошедший схему текст по-прежнему является черновиком.
