# Отдельная связка M15 → M5 → M1: историческое наблюдение

## Основание в уроке

В V3 01:55–03:22 автор описывает две последовательности периодов: H1 → M15 → M5 и более локальную M15 → M5 → M1. В V3 05:19–06:18 и 10:43–13:11 младшая свечная зона размещается внутри выбранной старшей; в V3 13:40–16:37 при отсутствии свечного уточнения рассматривается SNR. Сохранённые [карточки](ЭТАП_1_КАРТОЧКИ_ПРАВИЛ.md) подчёркивают: точная геометрия, срок зоны, форма M1-свечи и единый способ входа не определены. Вторая связка не требует автоматически переносить весь H1-фильтр из базового объяснения.

## Измеримая версия проекта

Это **отдельный наблюдатель вложенных свечных областей**, без заявки или P/L. Используются закрытые bid OHLC XAUUSD M1, из полных последовательностей собираются M5/M15. Наши допущения:

1. Старшая M15-область — весь диапазон свечи строгого поворотного минимума (BUY) либо максимума (SELL), подтверждённого двумя закрытыми M15 справа и слева. Область становится известна только после закрытия второй правой свечи. Это заменитель выбираемой человеком старшей свечной зоны; автор не требовал именно такую свечу.
2. M5 и M1-области — трёхсвечные FVG существующего `engine.fvg` с импульсом тела не меньше 0,5 ATR(14) и шириной зазора не меньше 0,05 ATR(14). Эти числа взяты из текущего исследовательского FVG-конфига и не приписываются автору.
3. Направление всех трёх областей одинаково. M5 FVG должна **полностью** помещаться в диапазон M15, M1 FVG — полностью в M5. M5 должна возникнуть не раньше поворотной M15; M1 — не раньше исходной свечи M5 FVG. Уже закрытая младшая область может быть известна раньше, чем подтвердится старшая; цепочка датируется последним необходимым закрытием.
4. При нескольких подходящих сочетаниях для одной M1 выбирается самое узкое M5, затем самое узкое M15, при равенстве — постоянный ID. Связка регистрируется один раз по каждой M1 FVG. Если M1-область уже касалась цены до полной сборки цепочки, состояние `previously_touched` хранится отдельно.
5. Остальные цепочки наблюдаются до первого последующего M1-пересечения самой узкой зоны: ask OHLC для BUY, bid OHLC для SELL. Это `touch_observed` **после закрытия M1**, не доказанное исполнение лимитной заявки и не подтверждение M1-свечой. Через 2 часа без касания цепочка истекает. Родительская M15-зона доступна до 24 часов, M5 до 8 часов, M1 до 2 часов. При разрыве M1 активная цепочка становится `incomplete`; агрегирование и список областей начинаются заново.

Видеоурок допускает не только FVG, а также работу с SNR, ручной выбор из нескольких зон и разные варианты входа. Поэтому эта версия покрывает **один свечной путь**, а не всю связку автора. Нет общего стопа/цели, H1-фильтра, торгового результата или Telegram-уведомления.

## Воспроизведение

`python -X utf8 -m app.nested_m15_m5_m1_research` создаёт `results/nested_m15_m5_m1_run.json` и `results/nested_m15_m5_m1_events.jsonl`. У каждой области и цепочки стабильный ID, события содержат хеш спецификации и исходного CSV. Будущие свечи применяются только для подтверждения уже прошедшего поворота, а время знания события остаётся временем последнего закрытия.
