# Буфер событий SBR и RBS

Дата проверки: 27 сентября 2026.

Раньше каждый вызов `state()` заново читал весь JSONL-журнал, создавал список всех записей и только затем выбирал последние 50. Время чтения и временный расход памяти росли вместе с журналом.

Теперь `SBRForward` и `RBSForward` при создании последовательно читают журнал и заполняют `deque(maxlen=50)`. Новое событие добавляется в буфер после записи, `flush()` и `fsync()`, до обращения к очереди уведомлений. `state()` возвращает список из буфера без повторного открытия журнала. Полный журнал и учёт дубликатов сохранены.

Проверка: `python -m unittest discover -s tests -q` — 150 тестов прошли. Новые тесты проверяют оба режима: восстановление последних 50 из 80 записей, добавление и вытеснение старой записи, подавление дубликата, сохранность 81 записи на диске, повторный запуск, отсутствие файлового чтения при запросе состояния и видимость записанного события после сбоя очереди.

Границы изменения: это ограничение буфера для выдачи событий, а не всей памяти процесса. Множество `seen`, история событий и уровней моделей продолжают расти. Журнал читается полностью один раз при создании объекта; внешние изменения файла в уже работающем процессе не отслеживаются. Предполагается один писатель — MT5-мост.

Радар и Telegram не запускались. Реальная доставка и проверка на новых котировках в этот этап не входили.
