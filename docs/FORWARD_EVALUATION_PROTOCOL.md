# Протокол forward-проверки Radar v2

Дата фиксации: 30 сентября 2026 года. Цель — оценить наблюдаемые сценарии FVG, SBR и RBS по новым данным, не смешивая техническую доставку сообщений с результатом стратегии.

## Период и данные

- Основной период наблюдения: с 30.09.2026 03:21 UTC (восстановление свечей MT5) до 25.11.2026 03:21 UTC. По окончании публикуется результат, даже если сигналов или исходов окажется ноль.
- Исходные журналы и снимки сохраняются без переписывания. Каждый отчёт фиксирует версии правил, источник MT5, границу времени, входные файлы и SHA-256. [Первый воспроизводимый срез](../results/v2_forward_evidence.md) остаётся отдельной ранней выборкой.
- Закрытые M1, выборочные bid/ask и извлечённые тики имеют разную полноту. Промежутки без M1 и простой наблюдателя отмечаются отдельно. Причину двух 120-минутных промежутков в истории брокера пока нельзя подтвердить; они не считаются ни доказанным закрытием рынка, ни автоматически потерянными торговыми сигналами.

## Когорты и метрики

Для каждой модели отдельно считать своевременные события, поздние события, планы без подтверждения, подтверждённые планы и подтверждённые доставки Telegram. Связывать план, подтверждение и исход по одному ID, одной версии правил и одному источнику. Поздний сигнал, устаревшая котировка или обязательная отсутствующая свеча исключают событие из когорты своевременных решений, но сохраняются в журнале.

FVG: условный вход и закрытие брать только из своевременно подтверждённых событий. Показывать число закрытых, открытых, исходов с разрывом, средний чистый R, чистый результат и просадку; отдельно — спред, комиссию, проскальзывание и правило неоднозначной свечи. SBR/RBS пока `live_signal_only`: их планы и доставки измеряются, но доходность и просадка остаются «не измеряются», пока не зафиксированы и не реализованы правила условного исполнения.

Наблюдение в течение восьми недель само по себе не доказывает преимущество. При менее чем 50 пригодных закрытых исходах одной модели результат по ней обозначается «недостаточно данных». Даже 50 исходов допускают только описательный вывод с неопределённостью; заявление об устойчивом преимуществе потребует отдельной независимой проверки. Модели не объединяются в одну доходность.

## Техническая приёмка

Новый естественный план должен пройти путь `forward-журнал → SQLite → /api/scenarios → карточка → Telegram API` с тем же ID, сроком, причиной и уровнями. Ответ Telegram API с `message_id` подтверждает приём сообщения сервисом; просмотр на телефоне проверяется отдельно человеком. После перезапуска и пропуска данных старый план не становится снова действующим и не отправляется повторно. Тестовые сообщения и синтетические сценарии не входят в торговую выборку.
