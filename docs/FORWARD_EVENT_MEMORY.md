# Очистка обработанных событий живых SBR/RBS

Дата: 27 сентября 2026.

После добавления буфера последних 50 записей оставалась другая растущая копия: `model.events` в живых SBR/RBS содержал все события с момента запуска, включая разогрев.

Теперь обёртки `SBRForward.ingest()` и `RBSForward.ingest()` очищают этот список после успешного завершения обработки свечи. Новые события наблюдения к этому моменту записаны в полный JSONL-журнал; последние 50 доступны через отдельный буфер. События разогрева, как и раньше, не записываются в forward-журнал, но больше не остаются в памяти. Исторические классы исследовательских моделей не изменены.

При исключении очистка не выполняется. Это сохраняет буфер для диагностики, но не добавляет автоматический повтор записи после ошибки диска. Восстановление уже записанного уведомления из журнала в очередь продолжает работать по прежним правилам.

Проверка: `python -m unittest discover -s tests -q` — 152 теста прошли. Для каждого режима выполнено сравнение с моделью без очистки на 3 600 синтетических M1-свечах, включая 300 свечей разогрева. Совпали все записанные события, уровни, свечные данные и список сделок; на каждом успешном шаге временный список событий пуст. Отдельно проверено сохранение буфера при ошибке открытия журнала и ошибке очереди. Это техническая проверка на синтетических данных, не оценка прибыльности или качества живых сигналов.

Остаются растущими `model.levels` и множество ключей `seen`. Изменение не ограничивает всю память процесса. Радар, MT5-мост и Telegram не запускались; реальных уведомлений не отправлялось.
