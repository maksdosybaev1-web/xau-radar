# Исправление времени наблюдения — 28.09.2026

Сбой устранён: API снова считает котировки свежими и готов принимать новые оповещения. Доказательства проверки: [clock_recovery_verification.json](../results/clock_recovery_verification.json).

## Причина и исправление

Системное UTC совпало с HTTP Date Google и Microsoft с расхождением около секунды. При этом изменяющиеся котировки XAUUSD и свежие M1 из установленного MT5 имели смещение +10800 секунд. Свечи попадали в будущее относительно системных часов и пропускались мостом.

[Документация MT5](https://www.mql5.com/en/docs/python_metatrader5/mt5copyticksrange_py) описывает временные метки как UTC. Поэтому поправка здесь относится к проверенному источнику, а не ко всем установкам MT5.

- `mt5_clock.json` хранит явную поправку 10800 секунд, привязанную к серверу и символу. Из возраста последней котировки смещение автоматически не вычисляется.
- `app/mt5_clock.py` преобразует M1/M5/M15/H1, котировки и миллисекундные метки тиков в UTC. Диапазон запроса тиков преобразуется обратно во время источника. Исходные массивы не изменяются.
- В `live.json` сохранены применённая поправка и исходное время котировки. Котировка из будущего после преобразования останавливает обработку с диагностикой; очередь также отвергает будущие и старые котировки.
- Поправка включена в идентификатор источника журналов и checkpoint. При смене сервера настройка не применяется молча.
- При сезонной смене времени брокера настройку потребуется перепроверить. Это постоянная поправка для текущего источника, не универсальная историческая модель часовых поясов.

Это короткая техническая проверка, а не доказательство непрерывности за длительный период или результата стратегии.

## Telegram

Read-only проверки `getMe` и `getChat` успешны. Одно новое тихое диагностическое сообщение получило `message_id=8`; затем в рабочей очереди появилась одна подтверждённая отправка `sent`. Неопределённые старые сообщения повторно не отправлялись. К моменту проверки таких записей было уже 16, а не 15; их фактическая доставка остаётся неизвестной.

Для следующих сетевых ошибок журнал сохраняет безопасное имя класса причины без текста исключения, URL и токена. Автоповтор после неопределённого ответа по-прежнему запрещён.
