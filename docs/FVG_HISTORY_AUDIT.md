# Зависимости истории FVG и оптимизация отчёта

Дата: 27 сентября 2026.

Проверены `engine.py`, `fvg_checkpoint.py`, `mt5_bridge.py`, `forward_assessment.py`. Простое обрезание истории движка сейчас меняет смысл расчётов:

- `curve` используется в `summarize()` для максимальной просадки по текущей стоимости портфеля, а в forward-отчёте — для количества новых M1.
- `trades` используется для статистики, сопоставления с подтверждёнными сигналами и восстановления ссылок открытых позиций. Новый ID сделки зависит от длины списка.
- `zones` также определяет новые ID через длину списка. Удаление старых зон без изменения этой схемы создаст повторные ID.
- `events` передаётся журналу и результату для интерфейса. Для его ограничения нужны согласованные архивирование, восстановление и доступ к старой истории.
- Снимок проверяет хеш `engine.py`; изменение движка требует явной совместимой миграции старого снимка, а не автоматического сброса.

Состояние существующего снимка при проверке: 15 событий, 0 сделок, 0 точек кривой, 7 зон, 5 дочерних зон и 240 свечей графика. Это снимок выключенного процесса, не измерение расхода оперативной памяти. Сам снимок не изменён.

Выполненное изменение: `forward_assessment.snapshot()` читает JSONL построчно и сразу обновляет счётчики и ключи подтверждений. Удалены полные промежуточные списки `records` и `timely`. Формат результата, граница наблюдения, проверка версии правил, учёт повторных событий и сопоставление со сделками сохранены. Множество уникальных подтверждений и загруженный `live.json` пока остаются в памяти.

Проверка: `python -m unittest discover -s tests -q` — 162 теста прошли. Добавлен сценарий с 1 000 приближений, повторным подтверждением, неизвестным качеством, событием до границы наблюдения и пустыми строками. Сохраняются прежние проверки просроченных данных, несовпадения правил и исходов с пропусками котировок.

Следующий этап архивирования движка: сначала определить независимые счётчики ID и накопительные метрики просадки/числа M1, затем миграцию снимка и чтение полной истории из архива. Приёмка должна сравнить непрерывный и перезапущенный прогон с исходной моделью, включая открытую позицию и ожидающий вход. В этом шаге история движка не обрезалась.

Радар, MT5-мост и Telegram остаются выключенными. Реальные сообщения не отправлялись.
